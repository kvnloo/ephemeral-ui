One card.
Every agent.

When an agent touches an app, a card shows up in the thread: the inbox it searched, the ride it priced, the PR it is about to merge. It looks like the app, lives in the host's theme, and dissolves when the task is done.

Studio apps too: three agents sculpting one mesh in Blender, a PCG city in Unreal, an FPV run, a voice-and-pen edit in fframestudio. The same card spec renders in Hermes, T3 Code, or anything that speaks it.

The kit

A card for every app your agent uses.

Each app maps to three card kinds that fit what it does. Tap a tile to play its cards live. Brand colours come from simple-icons; apps without a verified colour get a neutral tile instead of a guess.

No app matches. Try a category or a kind like “merge”.

Combos

Flows you can see.

Real work crosses apps. Say it however you say things and the kit draws the flow as a graph: the words you used become nodes, the apps you already use fill the gaps, and branches run side by side. Every wire carries a typed payload you can read in flight, every node shows what it did with it, and checkpoints wait for you. Prompt tersely and it asks once; ask to be walked through and it stops where it matters.

Card kinds

Fifty ways to show work, not tool calls.

Every kind is interactive: hold to confirm, drag to pick a time, swipe to archive, turn the knob, untangle the graph, resolve then merge. Each runs on any app in the kit and any host theme.

Cloud × Kubernetes × local ML

Connect services. Keep the boundaries.

Compose AWS, GCP, Lambda GPU Cloud, NVIDIA Brev and local services into one architecture. Inspect K3s, kind and managed Kubernetes examples, review IaC changes, and trace Unsloth training artifacts into local inference. Authored examples only: no cloud access, credentials or deployment.

Ripple × AODL × z0intelligence

Declare. Operate. Understand.

Three ephemeral kits for T3 Code: preserve the ask, expose the contract, follow the proof, and open the decision layers that matter. Eight new cards, plus OMP's trace and tools. Same host themes; no pretend approval.

Ask the trace

Ask your agent's event trace.

Type a question about a session. It becomes a small typed query plan: which omp-stats endpoints to call, which trace cards to show, with which layers. The cards look like the /stats dashboard and take its JSON as is, so you can scrub the timeline, open spans, sort tools and jump from a failure to the span that failed. Toggle layers to change what every card shows.

Stats library
Every /stats control, as a component.
The omp-stats dashboard taken apart: 18 primitives, 7 trace pieces, 11 route views and the whole app. Each one takes the /stats API JSON unchanged plus an options object, and reports what you click, pin, drag or filter as small typed events with entity ids (session, span, tool, model, request, time range), so a chat host can hand the selection to the agent for the next turn. Link one with #stats=<component>; the API is make(data, opts) → {el, spec, getSelection(), on(event, cb)} (card.v0.json → $defs.statsComponent).

Theme engine
Preview any host. Bend it to yours.
Presets are read from the hosts' own source: T3 Code's index.css and Hermes desktop's presets.ts, resolved to sRGB. Hermes keeps its near-square corners; T3 keeps its 8px radius and true-black dark mode.

Flows
Cards that hand off to each other.

Spec
Agnostic by contract.
A card is data, not code: a kind, an app, the facts it shows, and actions the host must confirm. The host owns rendering, theme and permissions, so a card can't spoof a host or act without you. Click any card on the page to see its spec here.
