One card.
Every agent.

When an agent touches an app, a card shows up in the thread: the inbox it searched, the ride it priced, the PR it is about to merge. It looks like the app, lives in the host's theme, and dissolves when the task is done.

The same card spec renders in Hermes, T3 Code, or anything that speaks it. Switch the host up top and the whole page re-skins from the real token files.

The kit

A card for every app your agent uses.

Each app maps to three card kinds that fit what it does. Tap a tile to play its cards live. Brand colours come from simple-icons; apps without a verified colour get a neutral tile instead of a guess.

No app matches. Try a category or a kind like “merge”.

Card kinds

Thirty ways to show work, not tool calls.

Every kind is interactive: hold to confirm, drag to pick a time, swipe to archive, turn the knob, untangle the graph, resolve then merge. Each runs on any app in the kit and any host theme.

Theme engine

Preview any host. Bend it to yours.

Presets are read from the hosts' own source: T3 Code's index.css and Hermes desktop's presets.ts, resolved to sRGB. Hermes keeps its near-square corners; T3 keeps its 8px radius and true-black dark mode.

Flows
Cards that hand off to each other.
An agent task is usually three apps in a row. Drag the cards around; the cables follow. Run it to watch work move down the line. Click a card to open it.

  

  






  
Spec
Agnostic by contract.
A card is data, not code: a kind, an app, the facts it shows, and actions the host must confirm. The host owns rendering, theme and permissions, so a card can't spoof a host or act without you. Click any card on the page to see its spec here.
